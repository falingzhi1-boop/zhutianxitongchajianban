# 1.1.5 正式版 · 更新说明

基于 1.1.4。这一版加了三个新功能，都来自玩家反馈：系统助手人设可以自定义、全部功能可以开关、聊天群可以读取世界书并召唤世界书里的角色。默认设置下，老用户的体验和 1.1.4 完全一样：人设仍是莉莉丝，所有功能都开着。

## 1. 系统助手人设（设置 → 上手 →「系统助手人设 ›」）

**三种预设：**

| 预设 | 说明 |
|---|---|
| 莉莉丝（默认） | 选这个时下面所有替换都不运行，插件对莉莉丝什么都不改。 |
| 系统光球（编号） | 没有人形的系统，一颗带编号的光球；冷静、简洁、按条播报。名字默认「系统＋编号」，头像是自动生成的 SVG 编号光球。 |
| 自定义 | 名字、称呼、性格、说话方式、头像都可以自己写。头像会裁成方形，压缩到 256 像素，限制 400 KB，以 data URI 存进扩展设置。高级选项里还能整段替换剧情规则和私聊人设。 |

**怎么生效：** 原版代码 `vendor/original` 带哈希锁定，这次没有改动。人设只在插件自己控制的环节里替换。

- **剧情**
  - SillyTavern 每轮扫描世界书时会发出 `WORLDINFO_ENTRIES_LOADED` 事件，事件里给的是条目的副本。在这些副本里：
    - 「诸天万界最强系统」的 `02｜核心｜系统助手莉莉丝` 换成人设规则，人设规则里自带台词格式 `【名字】：“……”`；
    - 其他诸天条目里的「莉莉丝」换成人设名。
  - 世界书文件不写入。浏览器测试确认，换人设后世界书文件里仍是原文。
  - 宿主没有这个事件时，改用一条深度 4 的覆盖提示。
- **私聊 / 记忆 / 工作台**
  - 在助手的私有 fetch 里，先按原文判断请求属于哪个分功能 API，再换内容：
    - 私聊的系统提示词 `PERSONA` 整段换成人设版。人设版保留原版的几条约束：只是私聊、不编造游戏操作、只输出说话内容、对话不改账本。
    - 其他系统消息里的名字也换掉。
  - 用户自己写的内容不改。
- **界面**
  - 助手 shadow root 里的文字、`title` / `aria-label` / `alt` / `placeholder`，以及原版头像图片，都按人设替换。替换前记下原值，所以换回莉莉丝时不用刷新就能恢复。
  - 下面这些不替换：输入框、私聊正文、工作台结果、记忆记录、群聊消息、人设页本身。
  - 语音框按人设名识别台词。
  - 分层立绘换成人设头像，带呼吸发光效果。
  - 悬浮莉莉丝只属于莉莉丝。换了人设后改用圆形头像唤醒按钮，拖到底部时也不再出现「换成莉莉丝」。

**涉及文件：**
- 新增：`src/persona.js`、`src/hub-persona.js`
- 修改：`src/voice-box.js`、`src/assistant-host.js`、`src/lilith-float.js`、`src/window-controls.js`、`src/hub-settings.js`、`index.js`

## 2. 功能开关（设置 → 上手 →「功能开关 ›」）

`src/hub-switches.js`（新增）把所有功能放进一张表，分 5 组共 37 项，另有「终端页面」「按聊天的开关」两组：

| 组 | 内容 |
|---|---|
| 系统助手 | 窗口、悬浮窗、语音框、触摸、震动、界面角色、页面台词、镜头、气泡播报 |
| 聊天楼层与数据块 | 记账、小标签、旧楼层过滤、守卫修复 / 补记 / 提醒 / 功法提示、变量宏、世界书自动安装 / 解绑 |
| 剧情提示 | 穿越、品阶提示 / 更正、熟练度 / 实战 / 角色卡同步、自拟外挂 |
| 聊天群 | 整个聊天群、自动闲聊总开关、读取世界书、群员记忆注入 |
| 界面与操作 | 速览、快捷键、斜杠命令、新手引导自动弹出、世界主题、演出、剧情提示卡片 |
| 终端页面 | 每个导航页面都能拿掉。总览、设置、连接一直保留；被关的页面点进去会提示。 |
| 按聊天的开关 | 记忆整理、聊天群摘要注入、外挂启用，这几项跟着聊天走，表里给出跳转。 |

- 表里的开关写的就是各功能原来读的那些设置。新增的设置键只有三个：`modules.{group, groupAuto, plugins, slash, guide}`、`navHidden`，以及聊天群用的 `groupWorld`。
- 关掉整个模块时，页面、注入和后台请求一起停：
  - 聊天群：注入清空，不再自动闲聊，降临倒计时暂停；
  - 自拟外挂：外挂提示词清空；
  - `/zt`：只回复“已关闭”。
- 只有「系统助手窗口」需要刷新后生效。
- 关掉的功能数据都保留。表上有「全部开启」。

## 3. 聊天群 × 世界书（聊天群 → 群员 →「从世界书召唤」）

`src/group-world.js`（新增）和 `src/hub-group.js` 一起实现。

- **召唤**
  - 选一本世界书（★ 表示当前聊天正在用；列表里没有诸天世界书），按名字或关键词查找条目（只读）。
  - 点「召唤」后，模型按条目内容输出一行资料（名称|出处|实力档|性格|特产），和招募令的格式一样。费用也一样：每次 100 点，失败退回；入群费按实力档。
  - 候选人和入群后的群员都会记下 `来源 {book, uid, comment}`。
- **群聊 / 私聊读取世界书**
  - 每次群聊、私聊时附上召唤群员自己的条目（每人约 360 字），再加上对话里关键词命中的同书条目（最多 3 条）。
  - 总预算默认 1,600 字，可以设成 400–6,000 字。
  - 群里没有召唤来的群员时，请求和 1.1.4 完全一样。
- **群员记忆**（设计决定）
  - 不写入世界书，只在账本里记来源。
  - 正文最近 4 层出现了群员的名字或条目关键词时，聊天群摘要里会多一段「群员记忆」：最近群聊、私聊、经聊天群送出的东西、好感，最多 3 人。
  - 生成开始时（`GENERATION_STARTED`）刷新这段内容，所以拿到的是最新正文。
  - 需要本聊天开着「剧情摘要注入」。可以在功能开关里关掉。

## 自检修订 r1（版本号不变，诊断里的「修订」显示 1.1.5-r1）

发布后对 1.1.5 的新代码做了一次自检，修了下面 5 个问题：

| # | 问题 | 后果 | 修法 |
|---|---|---|---|
| 1 | 聊天群里有世界书召唤的群员时，一轮群聊要先读世界书，读完才标记「群员正在输入」 | 读世界书那一刻（第一次可能要几百毫秒）连点发送、或刚好碰上剧情后自动闲聊，会**同时跑两轮**：两次请求、两轮回复都入账 | 先标记忙碌再读世界书；私聊同样处理 |
| 2 | 「功能开关」关掉聊天群后，诸天世界书里插件自带的常驻条目「36｜联动｜诸天聊天群（插件）」仍然每轮发给正文 AI | 正文 AI 仍以为宿主有聊天群，可能编造群聊、红包 | 关掉聊天群时，这条从本轮的世界书副本里去掉（不改世界书文件）；打开后恢复 |
| 3 | 群员记忆在 `GENERATION_STARTED` 时刷新，而酒馆在这之后才把你刚发的那句加入聊天 | 你这句话里第一次提到召唤的群员时，要到下一轮才注入记忆 | 另外在 `MESSAGE_SENT`（用户消息入聊天后、拼提示词前）刷新 |
| 4 | 换人设后，旧楼层、状态栏引擎自己发的消息（如「请给出莉莉丝的播报反馈」）和旧记忆里仍是「莉莉丝」 | 正文 AI 容易被带回去，继续用【莉莉丝】说话 | 人设规则末尾加一段「称呼对照」：这些地方的「莉莉丝」都指当前人设，按当前人设和台词格式回应。整段替换的自定义规则也会附上 |
| 5 | 人设名字可以只填 1 个字 | 例如填「我」，语音框会把正文里的「我说：“……”」都画成系统台词卡；名字里带 `$&` 一类字符时，语音识别的正则会被改坏 | 名字至少 2 个字（保存时提示）；正则替换不再展开 `$` 序列 |

新增测试：`tests/v115.test.js` 增加 5 项（含「读世界书期间已经是忙碌状态」的集成测试）；`tests/native_v115.py` 增加 3 项（称呼对照进入正文提示词；聊天群关闭时条目 36 不发送；重新打开后恢复）。

## 限制

- 自定义人设、系统光球、召唤和群员记忆的扮演效果都只用模拟模型验收过（实验性）。
- 其他世界书条目里的「莉莉丝」是机械替换，原版的成人向内容也会一起换成新名字。想彻底去掉，用「高级：整段替换」，或者直接编辑世界书。
- 已经写进聊天记录的旧台词、旧私聊不会被改。
