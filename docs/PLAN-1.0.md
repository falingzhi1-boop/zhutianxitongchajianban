# 诸天终端 1.0 更新方案（草案）

写于 0.9.4 之后（2026-10-02）。这份方案在 [ROADMAP-1.0](ROADMAP-1.0.md)（写于 0.9.0）的基础上，按 0.9.1–0.9.4 的实际进展重新排了一遍，并把每一步写成可以验收的条目。**确认后再并回 ROADMAP。**

---

## 一、1.0 的发布标准

一句话：普通用户按 README 安装，**用自己的真实模型**在电脑和手机上玩完一整局，全程不丢账本、不卡死、不需要看文档排错。具体是下面 6 道门，全部通过才发 1.0：

| # | 门 | 通过标准 |
| --- | --- | --- |
| 1 | 真实模型 | 3 类模型（国产大模型、思考模型、经中转站访问的模型）各跑完《一局验收脚本》；账本没有丢失或写坏；变量更新块的格式遵守率 ≥ 90%；格式不对时界面给出能看懂的提示，不会静默失败 |
| 2 | 能力表清零 | `src/contracts.js` 里现在的 6 项 `pending` 全部变成 `implemented`；做不到的明确标为「实验性」，并在界面上写出来 |
| 3 | 真机 | iPhone + Safari、中端 Android + Chrome、360 宽小屏、TauriTavern：每台走一遍「手机真机自检」和一局核心流程 |
| 4 | 宿主矩阵 | SillyTavern 支持范围内的每个版本，加上发布时的最新正式版，装 / 不装酒馆助手各跑一轮全部浏览器测试 |
| 5 | 数据安全 | 导出 → 改坏 → 导入或回滚 → 读回一致；账本有结构版本号和迁移测试；写好卸载说明 |
| 6 | 试玩期 | rc 期间至少一周，几位用户在自己的模型和手机上玩，没有数据丢失类问题，也没有未解决的严重问题 |

## 二、现状（0.9.4）

- **能力表**：45 项 `implemented`，6 项 `pending`，1 项只读。6 项 pending 里有 5 项卡在“没有真实模型”，1 项卡在“没做浏览器点击验收”（旧存档迁移、备份与回滚）。
- **测试**：单元测试 208 项；浏览器测试 16 套。只有 SillyTavern 1.19.0 是最近全部跑过的。
  - 1.17 / 1.18 从 0.8.2 起没有复测。
  - `native_replace040`（v1.1 一键接管）从 0.4.0 起没跑过，因为它需要不能上传的原版文件。
- **真机**：0.9.1 做了「手机真机自检」，Android 真机结果还没回传；iPhone、360 宽小屏、TauriTavern 实机都没测过。
- **体积**：仓库受版本控制的文件约 12.3 MB，其中 `docs/evidence/` 占 8.3 MB。酒馆用 `git clone` 安装扩展，所以每个用户都会下载这些截图和日志。
- **文档**：README 393 行，大半是逐版本的更新记录；仓库还没有 LICENSE；设置项 36 个，没有分组。
- **宿主**：SillyTavern 最新正式版是 1.19.0（2026-09-14）。酒馆官方在 2026 年 5 月的安全通告里说 1.17.0 之前的版本都不安全（起因是第三方扩展窃取 API Key）。插件目前的最低版本是 1.16.0。

## 三、版本计划

前面 4 个小版本各做一件事，然后冻结功能进入 rc。每一版都照现在的规矩来：改动的完整文件、版本号四处核对、CHANGES 和 ACCEPTANCE、单元测试和浏览器回归。

### 0.9.5 真实模型验收与格式容错（P0，最大缺口）

我这边没有、也不应该拿到你的 API Key，所以做法是**把验收工具做进插件里，由你在本地跑，只回传脱敏结果**。

1. **「模型体检」**（设置 → 兼容与维护，和「手机真机自检」放在一起）：
   - 用你已经配好的接口，按顺序发 6 个小请求：
     - 主聊天的变量更新块；
     - 写入当前世界 / 世界类型；
     - 商城进货；
     - 招募卡；
     - 群聊回复；
     - 私聊。
   - 每一项判定能不能解析、有没有乱写字段、耗时多少，最后一键复制报告。
   - 报告里只有模型名、接口类型、每项是否通过和失败原因，失败片段截前 80 个字并脱敏；**不含 Key，也不含聊天内容**。
   - 开始前会提示大约要花多少次请求。
2. **《一局验收脚本》**（`docs/REAL_MODEL_SCRIPT.md`）：
   - 固定测试角色卡，20 步操作：穿越 → 任务 → 商城 / 抽取 → 突破 → 聊天群 → 私聊 → 换聊天 → 关掉插件。
   - 每一步都写明通过标准：账本哪个字段应该变、世界书有没有注入、楼层里有没有残留的原始 `<ZhuTianPanel>`。
   - 你照着玩一局，用「复制诊断信息」把结果回传。
3. **格式容错**：
   - 先用一批“坏输出”样本写成单元测试（至少 30 条）：
     - 思考过程混在正文里；
     - JSON 包在代码块里；
     - 中文引号、全角冒号；
     - 字段名漂移（例如把「系统点」写成「积分」）；
     - 输出被截断；
     - 同一个块出现两次。
   - 再按你回传的真实报告补修。
   - 修不了的给出可读提示，例如“这个模型没有按格式写变量，本轮没有记账，可以重试或换模型”。
4. **验收**：
   - 3 类模型各有一份体检报告和一局脚本的结果，写进 ACCEPTANCE-0.9.5。
   - 能力表里 5 项和模型有关的 pending 按结果改状态。

**需要你**：提供 1–3 类模型在你本地跑，最好是 DeepSeek 或 GLM、一个思考模型、一个经中转站访问的模型。

### 0.9.6 数据安全闭环 + 补点剩余按钮（P0）

1. **整体导出 / 导入**：
   - 一个 JSON 文件包含设置、账本、聊天群、图谱缓存和引导状态，默认不含 API Key。
   - 导入前先自动备份一次，并先显示“将要覆盖什么”的差异预览。
2. **账本结构版本号**：
   - 新增 `诸天系统.结构版本`，配一套迁移函数，每一步迁移都有测试。
   - 读到比插件更新的版本时只读并提示，不会覆盖。
3. **备份与回滚**：做完浏览器点击验收，流程是“写入 → 改坏 → 回滚 → 读回一致”。能力表里「旧存档迁移、账本备份与回滚」改成 implemented。
4. **卸载说明**：停用 / 删除插件后，哪些数据还留在聊天元数据里、怎么清理、怎么回到 v1.1。
5. **补点按钮**：神通的支付类（复制、状态）、分身派遣、随身洞天、自定义次数抽卡。每个至少走一次“点击 → 写入账本 → 读回”，写进浏览器测试。

### 0.9.7 体验打磨（P1）

1. **设置分组**：36 个设置分成「常用 / 进阶 / 诊断」三组，进阶默认折叠，再加一个搜索框。
2. **统一错误提示**：
   - 所有失败提示都改成三段：发生了什么 / 账本有没有写入 / 下一步怎么做。
   - 把现有的报错文案过一遍，用一个单元测试检查格式。
3. **手机**：
   - 横屏左侧导航改成“常用 6 个 + 更多”，不用再滚动才能找到入口。
   - 低端机自动降级：系统开了“减少动态效果”时自动跟随；检测到明显掉帧时提示关闭演出动画。
4. **启动速度**：
   - 终端引擎、聊天群、图谱改成第一次打开时才加载，不在酒馆启动时一起加载。
   - 改前改后各测一次手机上酒馆的启动时间，写进验收报告。

### 0.9.8 发布准备（P1）

1. **README 重写**：
   - 结构改成：安装 → 上手（配合新手引导）→ 常见问题 → 更新 / 卸载，目标 150 行以内。
   - 版本历史移到 `CHANGELOG.md`；`docs/CHANGES-*.md` 保留，作为详细说明。
2. **LICENSE**：写清插件自写代码的许可，以及原版 v1.1 代码、莉莉丝立绘、Live2D Cubism Core 的授权边界（需要你决定，见第五节）。
3. **安装体积**：`docs/evidence/` 移到单独的 `evidence` 分支或 Release 附件，主分支只留报告文字，用户下载量约从 12 MB 降到 4 MB。0.9.1 时你决定暂缓，这里需要再确认。
4. **静态检查**：加 ESLint；先给桥接层和账本相关模块加 JSDoc，并用 `tsc --checkJs` 做类型检查。CI 一起跑。
5. **全矩阵**：
   - 支持范围内的每个 SillyTavern 版本加最新正式版，装 / 不装酒馆助手各跑一轮全部浏览器测试。
   - `native_replace040` 改成用一份可以公开的合成替身（结构和原版相同，不含原版内容），这样每次都能跑。
6. **版本门**：`minimum_client_version` 和 README 写的支持范围，要和实际测过的版本一致。

### 1.0.0-rc.1 → 1.0.0

- **冻结功能**，只修 bug，有修复就发 rc.2、rc.3。
- **真机清单**：按第一节第 3 条，每台设备人工走一遍，结果写进 ACCEPTANCE-1.0.0。
- **试玩**：3–5 位用户在自己的模型和手机上玩一周，用「复制诊断信息」反馈问题。
- **发布**：满足第一节全部 6 道门，并且 rc 最后一版发出后一周内没有数据丢失类问题，就发 1.0.0。

### 1.0 之后（1.x）

莉莉丝本人的 Live2D 模型、和酒馆群聊配合、多语言界面、用户自定义配色、平板专用布局。

## 四、风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 真实模型只能测到一两类 | 第 1 道门不完整 | 1.0 的说明里写清“已验收的模型”；没测过的模型类别标“未验证”，不笼统地说“支持” |
| 真机和试玩用户不够 | 第 3、6 道门拖期 | 优先保证你自己的手机和 TauriTavern；iPhone 找不到人测时，在说明里写“iOS 未实测” |
| rc 期间酒馆发布 1.20 | 版本矩阵要重跑 | 新版发布后补跑一轮矩阵；发现不兼容时先把版本门收紧，修好再放开 |
| 原版 v1.1 和立绘的授权不清楚 | LICENSE 只能覆盖插件自写的部分 | LICENSE 里分开写，原版部分注明来源和使用条件 |
| 数据迁移出错 | 用户丢档 | 每次迁移前自动备份；迁移函数必须有测试；读到更新的版本时只读 |

## 五、需要你决定的事

1. **真实模型**：你手上能用哪几类模型和接口？（决定 0.9.5 能验收到什么程度）
2. **最低支持版本**：保持 SillyTavern 1.16，还是提到 1.17（官方称 1.17 之前的版本都不安全）？
3. **许可证**：MIT（最宽松）、AGPL-3.0（和酒馆本体相同），还是暂不开源授权（保留所有权利）？
4. **证据文件**：`docs/evidence/` 在 0.9.8 移出主分支，还是继续保留？
5. **节奏**：按上面 4 个小版本走，还是合并成两个大版本（0.9.5 = 模型 + 数据，0.9.6 = 体验 + 发布准备）？
6. **试玩用户**：rc 期间能不能找到 3–5 位用户试玩一周？

## 六、执行结果（1.0.0，2026-10-02）

你的决定：① 暂不接真实模型，只用模拟模型；② 最低版本保持 SillyTavern 1.16；③ 许可证用「源码可见、保留所有权利」，禁止再分发、商用和 AI 训练；④ 证据文件“都可”；⑤ 一口气更到 1.0.0，不发中间版本和 rc；⑥ 没有试玩用户；另外新增：手机悬浮莉莉丝改为抠图人物。
