# 1.1.0-patch4 · 旧终端跨聊天读写修复

日期：2026-10-05。插件版本仍为 1.1.0，账本结构仍为 2。诊断页修订标记为 `1.1.0-patch4`。

## 出现条件和原因

在 A 聊天的终端打开弹窗或聚焦输入框，再切到 B。此前终端为了保留弹窗而延迟换页；旧页面的接口却按调用时的当前聊天取数据。A 页面扣 100 点可能写到 B：A 保持 1000，B 从 2000 变成 1900。

仅删除接口注册项不能解决：页面已经复制的函数、排队写入和等待模型返回的操作仍持有旧接口。

## 修复及范围

- 页面创建时固定原聊天身份、聊天数组和元数据对象。读、写、楼层查询及异步结果返回都检查这份绑定。
- 聊天变更通知、上下文替换或页面释放都会永久撤销旧接口；切回 A 也不能恢复已经失效的页面。
- 写入在取得锁后、执行更新器前后重新检查页面是否有效，覆盖等待锁和异步更新器期间释放页面的情况。
- 切换聊天优先移除旧终端，弹窗、输入框及生成状态不能阻挡；同一聊天的弹窗仍保留原有延迟换页行为。
- 强制重建时立即撤销旧接口，再做原有的短暂视觉过渡；监听器随页面释放清理。
- 本次只处理审查第 1 项。旧待领单件收下的两次保存、旧待领入包按名称与品阶合并这两项问题仍待修，不将本次检查通过描述为整个 1.1 已无 bug。

- 全套单元测试：348/348（此前 330 项加本次 18 项）。Windows 执行时仅将测试调用的 `python3` 指向现有 Python，未改项目测试逻辑。
- 项目静态检查：60/60，包含原始 vendor 来源核验；原始 vendor 未改动。
- Chrome 154.0.8037.93 隔离页面：9/9，运行实际 Bridge、Hub、StatusBarHost 与原版 3.1 终端脚本，使用真实浏览器 Web Locks，无真实模型请求。
- 浏览器覆盖弹窗切换、可见输入框聚焦及生成中切换、A→B→A、同名聊天上下文重载、锁队列、异步写入时强制重建、模型结果返回前切换、释放清理和新聊天正常扣点；无未预期页面错误。
- 旧 A 接口写入被拒绝后 A=1000、B=2000；新 B 页面正常扣 100 后 A=1000、B=1900。
- 输入框夹具最初试图聚焦隐藏管理员输入框，未实际获得焦点；改为可见输入框并同时断言焦点和忙碌状态后通过，未修改产品代码来迎合夹具。
