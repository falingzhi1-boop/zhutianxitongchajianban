## 修复内容

### 1. 聊天群异步回复串档

- 求助、私聊、群聊回复、直播在请求前捕获原聊天身份、聊天对象与正文状态。
- 发言后的群回复和自动闲聊也沿用原始捕获，不在等待结束后重新认定目标聊天。
- 提交前和锁内重新检查，把原始身份传入 Bridge。切换聊天、正文变化或生成状态变化时取消，不把回复写入当前的另一个聊天。
- 不在后台替用户重开原聊天、不静默重发模型请求。API请求已经发出的，供应商仍可能计费；这不代表扣了系统点。

### 2. 鉴定升阶错误合并、回收价抬高

- 升阶只修改原物品的品阶与鉴定记录，不再合并进同名同品阶的其它来源批次。
- 保留原价格、来源世界、原世界品阶、收纳凭据、数量。未标价旧物品仍按旧品阶冻结原回收估值，不随新等级提价。
- 鉴定候选使用包含来源和价格的批次键；旧名称/品阶键若对应多个来源，拒绝模糊选择并要求重新选择。
- 原生商城购买/公共入包和备用购买规划也避免吞并已鉴定或剧情收纳批次；退回物品保留其来源字段。
- 反例实测：补录价格1的古剑 + 商城价格10,000,000的同名仙品，各1件，鉴定后回收合计 **1,000,001点**，不再变成2,000,000点。
- 本修补不自动修复旧包已经发生的错误合并/错误回收；来源已丢失时不能可靠猜回数量和价格。请从错误操作前的备份恢复并人工核对，不自动扣回或发点。

### 3. 核验期间旧账本覆盖其它改账

- 写入前保存不可变账本快照与比较戳，同时固定聊天数组、元数据对象。
- 服务器核验返回后、执行更新器前、异步更新器返回后，重新检查页面账本及结算权限。
- 页面账本变化就拒绝这次提交，保留外部修改，不执行旧草稿覆盖，也不自动重跑扣费逻辑。
- 反例实测：余额100等待核验，宿主改为200，原扣10请求被拒绝，页面/服务器仍为200；用户刷新后重新确认扣款，得到 **190**，不是90。
- 这不是服务器端跨插件CAS事务。无法保证其它不遵循同一锁的进程在实际保存期间绝不竞争；原有保存后读回不一致/不明状态继续冻结，提示人工核对而非自动重复提交。

### 4. 保存环境与诊断

- 将误标的“HTTPS：是/否”改为分别报告 **安全上下文、连接协议、Web Locks、保存能力**。HTTP localhost 可以是安全上下文；HTTPS也不等于Web Locks一定可用。
- 设置页和连接页在保存前展示限制；受限环境的设置、变量和账本保存会拒绝，不能先改内存再假称保存成功。
- 非安全上下文：同机运行酒馆可使用 `http://localhost:端口` / `http://127.0.0.1:端口`；手机访问电脑必须使用浏览器信任的HTTPS访问方式，手机的localhost不是电脑。
- 安全上下文但没有Web Locks：提示换用支持它的现代浏览器，退出受限内嵌WebView，不让用户徒劳地只换HTTPS。
- 不建议关闭浏览器安全保护或给不安全源开白名单。切换访问源前先备份，不清空浏览器数据。
- 环境拒绝、Bridge写入拒绝、设置保存异常纳入最近报错。对于酒馆内部吞掉的延迟设置保存异常，识别宿主的固定错误前缀并记录通用故障，不抄录请求内容、密钥或私聊。
- 连接页成功文案改为“已提交给酒馆保存”，不把宿主的防抖调用返回当作服务器落盘凭据。HTTP 503故障注入验证：宿主捕获错误后，诊断中仍有“宿主设置保存”记录。
- 日志沿用最近30条、当前页面会话内存记录，刷新会清空；不是跨重启审计数据库。修订标记可在复制诊断中确认。
