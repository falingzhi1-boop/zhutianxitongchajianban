# 0.9.4 真实宿主浏览器验收

## 环境

- **宿主**：SillyTavern 1.19.0（官方 tag 全新安装，commit `7e8663c`），使用隔离的数据目录。
- **两轮测试**：
  - **没装酒馆助手**：跑全部浏览器套件（`native_replace040` 需要 v1.1 原版导入文件，本轮未跑）。
  - **装了酒馆助手**（JS-Slash-Runner 4.11.2，GitHub 官方 tag，未改动，页面上 `TavernHelper.getTavernHelperVersion()` = `4.11.2`）：跑 `native_v094`、`native_group060`、`native_v093`。
- **浏览器**：Playwright Chromium（无头），手机 390×844 触摸模拟（Android 14 / Chrome UA）。输入框用真实键盘输入（`keyboard.type`），下拉框用 `select_option`。
- **模拟模型**：5001 端口正常返回（请求里有「青丘」时返回白浅），5002 端口不发 CORS 头。

全程没有使用真实 API Key、真实聊天记录或 v1.1 原版导入文件。

## 用户复测

**待补。** 更新到 0.9.4 后：聊天群 → 群员 → 发布招募令，保持「随机世界」，在输入框里输入一个世界名，下拉框应自动变成「指定世界」；点「发布」后招来的人应来自这个世界。

## 复现：0.9.3 与 0.9.4 对比（`native_v094.py`）

同一个脚本先对 0.9.3 代码跑（3/9），再对 0.9.4 跑（9/9）。

| 场景 | 0.9.3 | 0.9.4 |
| --- | --- | --- |
| 输入框提示 | “世界或角色名（随机时可空）” | ✅ “随机时不用填；输入名字会自动改为「指定世界」”；指定世界 / 指定角色时提示随之变化 |
| 选着「随机世界」输入「青丘」 | ❌ 下拉框仍是随机世界 | ✅ 自动变成「指定世界」，文字保留 |
| 之后手动改成「指定角色」 | 可以 | ✅ 可以，文字保留 |
| 切回「随机世界」 | ❌ 文字还在（但不会被使用） | ✅ 输入框清空 |
| 「指定角色」不填名字就发布 | ❌ 扣 100 点并发出请求 | ✅ 提示“指定角色时请填写角色名。”，不扣费，没有模型请求 |
| 随机时输入「青丘」后发布 | ❌ 请求是“来自「…」类型世界”，招到 叶清寒（问剑宗）——和用户描述一致 | ✅ 请求是“来自世界「青丘」的一名角色”，扣 100 点，招到 白浅（青丘） |
| 「随机世界」不填名字发布 | 随机类型世界 | ✅ 不变，仍是随机类型世界 |
| 页面错误 | 无 | ✅ 无 |

0.9.3 那一轮里「指定角色」一项算通过，是因为旧提示文字里也含“角色名”；行为上 0.9.3 本来就允许手动选指定角色，这一项不是新功能。
