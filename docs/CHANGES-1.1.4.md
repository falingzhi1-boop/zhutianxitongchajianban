这是一个 bug 修复小版本，在 1.1.3 上增量修改。

- 插件版本 1.1.4。
- 账本结构版本 2 不变；世界书规则版本 1.1.1 不变，世界书不需要更新。
- 插件 ID、设置命名空间和存储键都不变，旧存档直接可用。
- 新增的数据只有聊天群里的 `轮次`（最近 5 轮的记录，重roll 要用）和 `设置` 里的 5 个新项，都写在 `诸天系统.聊天群` 里。

## 1. 聊天群

### 删除单条消息

玩家反馈：群里的消息不能删。

- 聊天页工具栏新增「🗑 管理」。打开后每条消息旁边都有 🗑，点「✓ 完成」退出。
- 普通消息、系统提示、你自己的发言：直接删除。
- 已经写进账本的东西不能删，点了会提示原因：
  - 你**抢过**的红包；
  - 你**自己发**的红包（已经扣过账，群员也已经领了）；
  - 你**领过**的赠礼。
- 没抢的红包、没领的赠礼：先确认，然后和消息一起作废。今日已收红包数会减回去。
- 删除只影响群消息，不会改动账本里的系统点或背包。

### 重新生成（重roll）

玩家反馈：需要重新roll；收过红包或接受过礼物就不能 roll，否则可以。

- 工具栏新增「↻ 重roll」，作用对象是**最近一轮**群员发言。一轮可以是你发消息后的回复，也可以是一次自动闲聊。
- 输入不变：你的那句话，或者自动闲聊时看到的那段剧情。你的发言会保留。
- 以下情况不能重roll，会提示原因：
  - 这一轮的红包你已经抢了；
  - 这一轮的赠礼你已经领了。
- 可以重roll 时，这一轮的这些东西会一起撤回：
  - 群员消息、截断提示；
  - 没抢的红包、没领的赠礼；
  - 今日已收红包数；
  - 红包节奏（距上次 / 间隔）；
  - 这一轮用掉的禁言轮数（前提是之后没人改过）。
- 新回复到达后，才会**在同一次加锁写入里**撤掉旧的一轮、写入新的一轮。如果请求失败或超时，旧的一轮原样保留。
- 只能重roll 最近一轮。1.1.3 及以前生成的消息没有轮次记录，不能重roll，但可以逐条删除。

### 截断

玩家反馈：群聊回复会被截断。

- 原因：聊天群每次请求的输出上限固定是 1200 tokens。如果 AI 接口设置里填了默认最大输出，就用那个值。6 个人发言、带红包格式、或者用思考模型时，很容易不够用。
- 现在模型报告「输出达到上限」（`finish_reason = length`）时：
  - 最后一行多半是半条，会被丢掉；
  - 群里会出现一条提示，建议「↻ 重roll」，或者调高输出上限 / 调低每条字数。
- 限制：只有走独立 API（自定义地址）时才能识别截断。走「酒馆主 API」时，酒馆只返回文字、不返回结束原因，所以识别不到。这种情况下，调高下面的输出上限就行。

### 群务 → 群聊生成（新设置）

| 设置 | 选项 | 默认 |
|---|---|---|
| 每次最少几人发言 | 1–6、8、10 人 | 1 |
| 每次最多几人发言 | 1–6、8、10 人 | 6 |
| 每条消息字数上限 | 120 / 200 / 300 / 400 / 600 / 800 | 300 |
| 带给模型的最近消息条数 | 8 / 16 / 30 / 50 | 16 |
| 输出上限（max tokens） | 自动 / 1200 / 2000 / 3000 / 4000 / 6000 / 8000 | 自动 |

- 默认值和 1.1.3 的行为一样（1–6 人、300 字、16 条）。
- 下限大于上限时，另一项会跟着调整。
- 自动闲聊最多 3 人；下限高于 3 时按下限。
- 「自动」的计算方式：`600 + 最多人数 × (每条字数 + 20)`，限制在 1200–6000 之间。
- 输出上限的优先级：
  1. 「分功能 API」里给聊天群单独设的上限（最高）；
  2. 这里选的具体数值；
  3. AI 接口设置里的默认上限；
  4. 自动估算。
- 1.1.3 里，默认上限会盖过聊天群自己的值；现在你在这里选了具体数值，就以它为准。

## 2. 「此前原生结算写入状态不明…已冻结」（假冻结）

玩家反馈：账本被冻结了，但其实已经写进去了。

原因：写入账本后要从服务器读回来核对。以前比对的是**整个** `chat_metadata.variables`，而且逐字比较。下面这些情况都会被当成「写入状态不明」并冻结：

- 其他角色卡或脚本的变量（MVU 等）刚好在这时变了；
- 某个值服务器原样存不下，比如 `undefined` 或 `NaN`；
- 酒馆自己更早发出的一次保存后到，覆盖了这次写入。

修复：

- 读回时**只比对这次写入改过的变量键**，而且先按 JSON 规范化再比，其他卡的变量不再参与。
- 读回不一致时，先等 0.7 秒，把页面上的账本再存一次、再读一次。还不一致，才判定为「写入状态不明」。
- 原生结算（`ledger-service`）读回不一致时，也会再读一次。它不会自动重写。
- 冻结提示改为指向新按钮。

新按钮：**设置 → 诊断与维护 →「核对并解冻账本」**

- 只读，不写任何东西。比对服务器上的存档和当前页面的账本：
  - **一致**：没有悬而未决的写入，直接解冻，不用刷新。如果之前那笔其实没生效，重新提交一次就行。
  - **不一致**：会列出不同的项，并询问是否重载页面。重载后以服务器存档为准，冻结自动解除。
- 冻结状态只保存在页面内存里，所以重载页面本来就会解除冻结。这个按钮的作用是：不刷新也能确认、能解冻。

## 3. 「记忆整理失败：记忆键重复或不安全」

原因：原版校验器（`vendor/original/runtime.js`，有哈希锁，不能改）对记忆键的要求是：

- 只能用中文（U+3400–9FFF）、英文字母、数字、`_`、`-`、`/`；
- 1–64 个字符；
- 不能包含 `__proto__` / `constructor` / `prototype`；
- 同一批里不能重复。

模型常写出不符合要求的键，比如「林雪·关系」「任务：取钥匙」「Lin Xue」、日文假名、全角字母，或者同一个键写两次。只要有一个不合格，整批记忆都会被丢掉。

修复在 `src/model-response.js` 的 `normalizeMemory`，它会在原版校验**之前**运行：

- 先做 NFKC 规范化，所以全角会转成半角；
- 不允许的字符换成 `_`，危险词也换掉；
- 首尾的 `_` / `/` 去掉，长度截到 64；
- 清洗后什么都不剩的键，按内容生成 `mem_<哈希>`；
- 同一批里重复的键只保留**后面**那条。原版提交时同一个键也是后写的覆盖先写的，所以结果一致。

原版校验本身没有改动，其他规则照常生效（最多 12 条、证据必须出现在原文里等）。

## 4. 思维链标签被「卡掉」（图 6）

结论分两部分：

- **非诸天聊天**：没有复现，也没有找到插件改写非诸天聊天的路径。

- 两张截图是两次不同的生成，一次是日文思维链，一次是中文思维链，不能证明是插件改了显示。
- 数据块守卫只处理诸天存档，或者正文里带 `<ZhuTianPanel>` 的楼层。
- 楼层渲染只处理带数据块、莉莉丝台词或宏的楼层。
- 样式表里没有针对思维链的规则。

  最可能的原因是预设、其他扩展或正则冲突，玩家自己也这样判断。
- **诸天存档**：在隔离酒馆 + 模拟模型里**复现了一条真实路径**。模型在 `<think>` 里写了一个没闭合的 `<ZhuTianPanel>` 草稿，正文末尾再写正式数据块时：
  - 楼层渲染、账本绑定、旧楼层过滤用的都是「从第一个开始标签到第一个结束标签」的匹配，于是草稿和正式数据块的结束标签配成一对，把 `</think>`、正文和正式数据块一起吞进「数据块」；
  - 结果：思维链结束标签和正文从楼层上消失（看起来就是「CoT 标签被卡掉」），小标签显示「系统点 草稿」，正式数据块没有入账，莉莉丝语音框一张都没有；
  - 旧的标签补全还会把草稿当成没闭合的数据块去「修」。
- 另外，原版世界书有 3 条常驻条目插在**深度 0**（04 状态栏数据块与实时数据、05 状态栏规则补充、34 统一实力标尺与报价口径，合计约 3,700 字），会排在最后一条消息之后。靠最后一条消息或预填充开启思维链的预设可能因此失效。这是世界书的设计，插件不改（原版文件有哈希锁）；说明书里写了怎么自行调成深度 1–2。

这一版的修复和加固：

- **思维链里的数据块草稿停用**：新回复里，数据块**外面**的思维链中出现的 `<ZhuTianPanel>` / `</ZhuTianPanel>` 改成全角 `＜ZhuTianPanel＞`，阅读不受影响，但任何解析器（包括有哈希锁、不能改的原版内核）都不会再把它当成数据块。原文备份在楼层里，可以还原。新问题类型 `cotpanel`。
- **旧楼层也安全**：楼层渲染（`splitPanels`，同时决定账本绑定哪一个数据块）、`stripPanels`、旧楼层数据块过滤（`stripOldPanels`）都会先跳过数据块外的思维链，所以 1.1.4 以前保存的这类楼层也能正确显示、正确入账，正文不会再被过滤掉。

- **思维链保护**：数据块**外面**的思维链在修复前会换成占位符，修复后原样放回。包括：
  - 开头的 `<think>` / `<thinking>` / `<reasoning>` / `<analysis>` / `<思考>`…；
  - 预填充时只有结束标签 `</think>` 的情况；
  - 回复被截断、没有闭合的思维链。
- 思维链里的数据块草稿不再当真：标签不会被补全，也不会被移动（只会改成全角，见上）。
- 如果数据块**只**写在思维链里，就把它移到正文后面。思维链本身的标签保持不变，同时记为「数据块只写在了思维链里」。
- 思维链没闭合时（回复被截断）：本层不做其他修复，也不补记（草稿标签照样停用）。
- 放回时会检查每一段思维链是否都原样回来了。不满足就整条回复保持原样，不做任何改动。
- 数据块**里面**的 `<think>` 照旧移到酒馆推理框（1.1.1 的行为不变）。
- 莉莉丝语音框不再从思维链里提取台词。
- 格式提醒：
  - 默认插入深度从 0 改为 **1**。深度 0 时，系统提示会插在「预填充 / 思维链开头」之后，有的预设会因此乱了格式。
  - 可以在 设置 → 数据块格式守卫 →「格式提醒插入深度」改回 0。
  - 提醒文字里去掉了「思考过程」一词。
- 新增 **设置 → 诊断与维护 →「检查最新楼层：插件动过吗？」**，会列出：
  - 这个聊天是不是诸天存档；
  - 最新一层正文有没有被数据块守卫改写过（有备份就可以还原）；
  - 正文里有几段思维链，推理框里有没有内容；
  - 这一层是不是由插件渲染的；
  - 当前**所有扩展**注入的提示，包括位置、深度和角色，诸天的会标出来。
  - 结果会尝试复制到剪贴板，反馈问题时直接粘贴。
